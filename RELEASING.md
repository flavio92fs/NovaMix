# Publish a Windows release

1. Commit only the source tree. Use GitHub’s private commit email if you want to keep your personal email out of public commit metadata. Review the staged files for local configuration, caches, device identifiers, diagnostics and credentials before pushing.
2. Build with `.\build-release.ps1 -Frontend Iced`. Verify the installer checksum and test clean deployment and an upgrade in an isolated test folder. Run `.\native-ui\verify-preview.ps1 -AppDirectory <extracted-app-folder>` and the Rust tests with `.\build-native-ui.ps1 -RunTests`. Verify native rendering at multiple window sizes, inspect `frontend/licenses/INDEX.txt`, and check that the native package contains no Electron runtime. Run the optional Electron shell test only for legacy builds.
3. On GitHub, open **Releases → Draft a new release**. Choose the tag `v0.21.0-alpha.3` for this preview, use **NovaMix 0.21.0-alpha.3 — Native Iced preview** as the title and copy the matching [changelog entry](CHANGELOG.md). Target the `feat/native-iced` branch commit. Mark this release as a **prerelease** and do not replace the latest stable release.
4. Upload **`NovaMix-Setup-x64.exe`** and **`NovaMix-Setup-x64.exe.sha256`**. Leave the asset names stable so a download URL ending in `/releases/latest/download/NovaMix-Setup-x64.exe` keeps working across releases. Verify the draft and then publish it.
5. If the repository is renamed, update any bookmarks, clones and links that include its old URL. The NovaMix engine uses an independent loopback connection. See [GitHub’s release link documentation](https://docs.github.com/en/repositories/releasing-projects-on-github/linking-to-releases) and [repository rename behavior](https://docs.github.com/en/repositories/creating-and-managing-repositories/renaming-a-repository).
